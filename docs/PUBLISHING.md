# GitHub Pages and Actions

The live CUDA app is published at **https://SamG-Coder.github.io/ShoreBreak/**.

Every push to `main` runs `.github/workflows/pages.yml`. Its reusable checks in
`ci.yml` install dependencies, compile `ShoreBreak.cu`, run the CPU/artifact tests,
verify asset licenses, build for the repository subpath, and check the deployed
asset URLs on both Linux and Windows. Pull requests run the same checks without
publishing. GPU numerical comparisons remain available through the tools and
require a hardware-accelerated browser; hosted CI does not claim to run them.

After the checks pass, a separate build job uploads `dist/` as a Pages artifact.
Only the deployment job receives Pages write and OIDC permissions. The
`github-pages` environment records the deployment and its URL. Workflows can also
be started manually from the Actions tab.

Repository Settings → Pages must use **GitHub Actions** as the publishing source.
The workflow uses the repository name as `VITE_BASE_PATH`, so a fork can publish
under its own project path. For local testing of the Pages build in PowerShell:

```powershell
$env:VITE_BASE_PATH = '/ShoreBreak/'
npm run build
node tools/pages-check.mjs
npm run preview
```

Open the preview address followed by `/ShoreBreak/`. Ordinary `npm run dev`
without that environment variable still works at the root. WebGPU requires
HTTPS outside localhost. The first visit may spend several minutes compiling
native graphics programs and warming up the original simulation.

The only application GPU source is `ShoreBreak.cu`. Compiled files under
`public/faithful/`, dependency installs, build output, and local captures are
ignored by Git and regenerated by the build/tools. Keep the bundled source
assets, credits, and licenses when publishing `dist/`.
